🎯 Problem & Solution

Why a Knowledge Graph?

Movie information on the web is unstructured — keyword search fails for relationship-based questions, and LLMs hallucinate. We solve this with a formal ontology grounded in real data.

🧠

OWL Ontology

Formal modeling of films, people, genres, production companies, and countries with defined classes and properties.

🔗

Automated Reasoning

OWL-RL materializes inverse properties, super-properties, and defined classes — the MultiTalented class is inferred automatically by HermiT.

📊

10 SPARQL Queries

Basic retrieval, reasoning-dependent, and aggregation queries — each traced to a competency question.

✅

SHACL Validation

Class, property, cardinality, and value-range constraints enforce data quality across every movie and person.

🤖

LLM Integration

Natural language → SPARQL → grounded answer pipeline. Schema-constrained generation + result grounding eliminates hallucination.

🌐

TMDb Data

200 top-rated movies with 1030+ people sourced from The Movie Database API — real, rich, production-quality data.

Knowledge Engineering Pipeline

The full pipeline from data acquisition to LLM-grounded question answering.

1

Data Acquisition

Fetch top-rated movies from TMDb REST API (v3) — titles, years, runtimes, ratings, genres, directors, cast, companies, and countries.

fetch_tmdb.py TMDb API JSON
2

Ontology Design (TBox)

Define OWL classes (Movie, Person, Genre, ProductionCompany, Country), object properties with inverses and super-properties, data properties, and the defined class MultiTalented.

movie_ontology.ttl Protégé OWL
3

Knowledge Graph Construction

Transform JSON data into RDF triples (ABox). Merge with ontology TBox. Materialize inferred triples with OWL-RL reasoner.

build_graph.py RDFlib OWL-RL
4

SPARQL Querying

10 queries across 3 categories — basic retrieval, reasoning-dependent (inverse/super-property), and aggregation (COUNT, AVG, GROUP BY).

queries.py SPARQL
5

SHACL Validation

Enforce data quality with shape constraints: cardinality, datatype, value-range, and class constraints on Movie and Person instances.

validate.py shapes.ttl pyShACL
6

LLM-Grounded QA

Natural language → SPARQL (schema-constrained) → execute → grounded natural language answer. Zero hallucination by design.

llm_nl2sparql.py Gemini API

🔍 Queries

SPARQL Queries

10 queries organized into three categories, each mapped to a competency question.

Basic CQ1 — Movies directed by a specific director
▼
❓ Belirli bir yönetmenin yönettiği filmler hangileri?
SPARQL 
SELECT ?title ?year WHERE {
  ?p mov:personName ?pn .
  ?m mov:directedBy ?p ;
     mov:title ?title ;
     mov:releaseYear ?year .
  FILTER (STR(?pn) = "Christopher Nolan")
} ORDER BY ?year
Basic CQ2 — Release year and runtime of a movie
▼
❓ Belirli bir filmin çıkış yılı ve süresi (dakika) nedir?
SPARQL 
SELECT ?year ?runtime WHERE {
  ?m mov:title ?t ;
     mov:releaseYear ?year ;
     mov:runtime ?runtime .
  FILTER (STR(?t) = "Inception")
}
Basic CQ3 — Actors in a specific movie
▼
❓ Belirli bir filmde hangi oyuncular rol almış?
SPARQL 
SELECT ?actor WHERE {
  ?m mov:title ?t ;
     mov:hasActor ?p .
  ?p mov:personName ?actor .
  FILTER (STR(?t) = "Inception")
} ORDER BY ?actor
Reasoning CQ4 — Movies a person acted in (inverse property)
▼
❓ Belirli bir kişi hangi filmlerde oyunculuk yapmış? (actedIn = hasActor⁻¹ ile çıkarsanır)
SPARQL — Inverse Property Inference 
SELECT ?title WHERE {
  ?p mov:personName ?pn .
  ?p mov:actedIn ?m .   # actedIn = hasActor'ın ters özelliği (çıkarsanır)
  ?m mov:title ?title .
  FILTER (STR(?pn) = "Clint Eastwood")
} ORDER BY ?title
Reasoning CQ5 — All contributors to a movie (super-property)
▼
❓ Belirli bir filme katkı sağlayan herkes kim? (hasContributor üst-özellik)
SPARQL — Super-property Inference 
SELECT DISTINCT ?name WHERE {
  ?m mov:title ?t ;
     mov:hasContributor ?p .  # directedBy + hasActor üst-özelliği
  ?p mov:personName ?name .
  FILTER (STR(?t) = "Inception")
} ORDER BY ?name
Reasoning CQ6 — People who are both director and actor
▼
❓ Hem yönetmen hem oyuncu olan kişiler kimler? (MultiTalented — tanımlı sınıf)
SPARQL — Defined Class Reasoning 
SELECT DISTINCT ?name WHERE {
  ?p mov:directorOf ?m1 .  # ters özellik (çıkarsanır)
  ?p mov:actedIn   ?m2 .  # ters özellik (çıkarsanır)
  ?p mov:personName ?name .
} ORDER BY ?name
Aggregation CQ7 — Movie count per genre
▼
❓ Her türde (genre) kaç film var?
SPARQL — COUNT + GROUP BY 
SELECT ?genre (COUNT(?m) AS ?n) WHERE {
  ?m mov:hasGenre ?g .
  ?g mov:genreName ?genre .
} GROUP BY ?genre ORDER BY DESC(?n)
Aggregation CQ8 — Most prolific director
▼
❓ En çok film yönetmiş yönetmen kim?
SPARQL — COUNT + LIMIT 
SELECT ?director (COUNT(?m) AS ?n) WHERE {
  ?m mov:directedBy ?p .
  ?p mov:personName ?director .
} GROUP BY ?director ORDER BY DESC(?n) LIMIT 1
Aggregation CQ9 — Average rating per genre
▼
❓ Tür bazında ortalama film puanı nedir?
SPARQL — AVG + GROUP BY 
SELECT ?genre (ROUND(AVG(?r)*10)/10 AS ?avgRating) WHERE {
  ?m mov:hasGenre ?g ;
     mov:rating ?r .
  ?g mov:genreName ?genre .
} GROUP BY ?genre ORDER BY DESC(?avgRating)
Basic CQ10 — Post-2010 Science Fiction movies
▼
❓ 2010 sonrası çıkmış bilim-kurgu filmleri hangileri?
SPARQL — FILTER with compound condition 
SELECT ?title ?year WHERE {
  ?m mov:hasGenre ?g ;
     mov:title ?title ;
     mov:releaseYear ?year .
  ?g mov:genreName ?gn .
  FILTER (STR(?gn) = "Science Fiction" && ?year > 2010)
} ORDER BY ?year
🛡️ Quality

SHACL Validation

Shape constraints ensure data quality — every Movie and Person instance is validated against strict rules.

shapes.ttl 
@prefix sh:   <http://www.w3.org/ns/shacl#> .
@prefix mov:  <http://example.org/movie#> .

mov:MovieShape a sh:NodeShape ;
    sh:targetClass mov:Movie ;
    sh:property [ sh:path mov:title ;
                  sh:datatype xsd:string ;
                  sh:minCount 1 ; sh:maxCount 1 ] ;
    sh:property [ sh:path mov:releaseYear ;
                  sh:minInclusive 1888 ;
                  sh:maxInclusive 2030 ] ;
    sh:property [ sh:path mov:rating ;
                  sh:minInclusive 0 ;
                  sh:maxInclusive 10 ] ;
    sh:property [ sh:path mov:directedBy ;
                  sh:minCount 1 ;
                  sh:class mov:Person ] ;
    sh:property [ sh:path mov:hasGenre ;
                  sh:minCount 1 ;
                  sh:class mov:Genre ] .
✅ Conforms: True

python validate.py — Clean data passes all constraints

  • ✓ Every movie has exactly 1 title (string)
  • ✓ Release years in 1888–2030 range
  • ✓ Ratings within 0–10 range
  • ✓ Every movie has ≥1 director (Person)
  • ✓ Every movie has ≥1 genre (Genre)
  • ✓ Every person has exactly 1 name
❌ Conforms: False

python validate.py --demo — Injected errors caught

  • ✗ "Bozuk Film" — rating 99 → value-range violation (0–10)
  • ✗ "Bozuk Film" — no director → cardinality violation (min 1)
  • ✗ person_GHOST — no name → cardinality violation (min 1)
🤖 AI-Powered

LLM-Grounded QA

Natural language questions are translated to SPARQL by an LLM, grounded in the knowledge graph to eliminate hallucination.

1

User asks a question

"Christopher Nolan hangi filmleri yönetti?"

2

Schema-constrained SPARQL generation

LLM receives the full ontology schema (classes + properties) and generates ONLY a SPARQL query — no fabricated data.

3

Query execution on KG

Generated SPARQL runs against movies_inferred.ttl using RDFlib. Results are real graph data.

4

Grounded answer generation

LLM receives ONLY the query results and produces a natural language answer. Empty results → "Veri bulunamadı." — zero hallucination.

🔒

Schema Constraint

LLM receives exact class & property names — can only use what exists in the ontology.

📌

Result Grounding

Final answer is generated ONLY from SPARQL result rows — no external knowledge injected.

🚫

Empty = Honest

If the query returns no results, the system says "Veri bulunamadı" instead of making up an answer.

Mandatory Paper Review

"Personalized Ontology and Deep Training Tree-Based Optimal GRU-RNN for Prediction of Students' Behavior"

Core Methodology:

The study proposes a hybrid system combining personalized ontologies with deep learning (GRU-RNN with decision tree optimization) for student behavior prediction. The ontology captures student attributes, academic performance, and behavioral patterns as formal concepts, while the GRU-RNN handles temporal prediction over sequential data.

Key Contributions:
  • ✦ Personalized ontology construction per student profile
  • ✦ Tree-based optimization for GRU-RNN hyperparameters
  • ✦ Integration of symbolic (ontology) and sub-symbolic (neural) representations
  • ✦ Improved prediction accuracy through ontology-guided feature selection
Adaptation to Our Project:

While our domain differs (movies vs. education), the core idea of using ontologies to structure features for downstream ML is transferable. Our ontology could similarly guide feature extraction — e.g., ontology-driven feature vectors for movie recommendation or trend prediction. The neurosymbolic approach parallels our LLM + KG integration.

Ontology Design Methodology

Our ontology was designed from scratch using a structured approach, without extending an existing external ontology.

Methodology: METHONTOLOGY
  • 📌 Specification — Domain: movie industry, Purpose: structured QA over film data
  • 📌 Conceptualization — Identified core concepts (Movie, Person, Genre, etc.) and relationships
  • 📌 Formalization — Expressed in OWL with Protégé, including defined classes and inverse properties
  • 📌 Implementation — Turtle format, automated reasoning with HermiT/OWL-RL
  • 📌 Evaluation — Validated via competency questions (CQ1-CQ10) and SHACL constraints
📐

Design Patterns Used

  • 🔗 Roles as Properties (not Types) — Director/Actor modeled via properties, not separate classes. Enables a person to be both without type conflict.
  • 🔄 Inverse Properties — directorOf ↔ directedBy, actedIn ↔ hasActor — enabling bidirectional traversal via reasoning.
  • ⬆️ Super-property Abstraction — hasContributor subsumes both directedBy and hasActor for unified contributor queries.
  • 🧠 Defined Class (MultiTalented) — Inferred automatically by OWL reasoner for people who are both directors and actors.
